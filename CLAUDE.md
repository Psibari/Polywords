# POLYWORDS Architecture

Durable implementation map, not a session diary. `AGENTS.md` owns repository authority and safeguards; `CONTEXT.md` owns the current state and next task. Focused specifications own product detail. Executable code and canonical data establish what actually ships; when a doc disagrees with code, the code is the fact and the doc gets fixed. Old decisions and experiments live in Git history.

Do not hard-code live content counts here; run `npm run state`.

## Runtime and entry points

- Expo SDK 57, React Native 0.86 New Architecture, strict TypeScript. Zustand/immer and AsyncStorage own gameplay state and persistence.
- `App.tsx` owns navigation, boot and audio-app-state wiring. `app/screens/` owns screens; `app/store/useGameStore.ts` owns durable game progress.
- `app/game/huntGenerator.ts` and `app/game/polyRunEngine.ts` own Hunt selection and outcomes. `app/components/MaskBoard.tsx` and `app/components/SwipeMask.tsx` own cards and swipe behavior.
- `app/game/dailyChallengeEngine.ts` combines Daily pools. `app/ui/` owns reusable presentation constants/materials.
- React Native Animated drives most presentation; Reanimated drives finger-tracked cards. Do not refactor either gesture owner without a focused request.
- Production is `POLYWORDS` / `com.pdb8080.polywords`. Phone iteration uses the separate `POLYWORDS DEV` / `com.pdb8080.polywords.dev` client: `APP_VARIANT=development npx expo start --dev-client`. Add `-c` only for a Metro cache problem. JS/TS/art changes use Metro; native dependencies/config/SDK and splash changes need a new native build. TestFlight is for production-native checks.
- App icon and splash artwork are Pete-approved. `assets/icon.png`, `assets/adaptive-icon.png` and `assets/splash-icon.png` are hand-made, not generated by `scripts/generate-brand-icons.ts`. Do not overwrite or redesign them. Splash config and ready/hide timing live in `app.json` and `App.tsx`; hide only when navigation is ready, not on the root layout callback.

## Hunt contracts

- UP claims a REAL; RIGHT rejects a trap. No left swipe or tap-submit. Ordinary choices remain neutral before commitment.
- **Every Hunt is eight rounds with six starting feathers** (Pete, 2026-11-20, from friend-tester feedback). Arc: confidence 1-2, flow 3-4, tension 5-6, panic 7, Boss 8. An eligible Returning Haunt takes round 4 (normal-round presentation, never Boss presentation). First-run FINE and the mercy taper (`app/game/mercyPolicy.ts`) are unchanged. Ten-round generation is a test-only override; the pre-merge ten-round code is kept on `backup-play-screen-overhaul-10-round-pre-merge-2026-11-20`.
- A word encounter deals up to five visible cards from its larger approved pool. A card in live JSON is eligible to rotate, not guaranteed to appear in a particular Hunt.
- Ordinary words are picked by difficulty, not gpsTag: rounds 1-2 easy, 3-4 easy+medium, 5-6 medium+hard, 7 hard; mastered returns only in rounds 5-7. Only the `boss` tag still decides anything.
- **Full variety (Pete, 2026-11-20):** every ordinary word is played once before any ordinary word repeats. `app/game/huntRecency.ts` remembers every word met (finished and quit Hunts alike); the generator deals any unplayed word from the round's allowed pools before a remembered one, and replays oldest first. When the unplayed easy words run out, rounds 1-2 take unplayed medium (later hard) words rather than repeat. Haunts, the pinned Boss and mastered returns sit outside the cycle; a mastered word can return in rounds 5-7 once it is outside the last 30 words played. `app/game/huntReachability.test.ts` guards all of this (generator-level simulation, not real players).
- Boss outcome is determined by the three hidden judgments, never the score: all correct means MASTERED; a hidden miss or Boss death means HAUNTED. Returning Haunts retry the saved exact hidden pair; success banishes the active Haunt.
- The Boss is pinned across Hunts until the player reaches it, provided it remains eligible. `app/game/pinnedBoss.ts` and its test own the invariant.
- MASTER'S REMATCH appears only after the ordinary unbeaten Boss pool is exhausted. A rematch win is KING, increments the persistent `kingWins` once and creates no extra mastery/crown; a loss is BUSTER and creates no Haunt. `app/game/kingWins.ts` owns the idempotent counter.
- Momentum is STEADY, SHARP, RAZOR SHARP, UNTRAPPABLE, with FELL OFF on a broken chain. At armor threshold, one wrong call consumes the armor rather than a feather but still breaks the chain. Presentation constants live in `app/ui/momentumAccent.ts`, `app/components/wallShake.ts` and the HUD code; do not revive rejected grout/vein glows or torches.
- HUNT PAUSED preserves the active run through HOME or SETTINGS. QUIT HUNT is the explicit destructive action and must warn truthfully. Tests: `app/game/huntPauseNavigation.test.ts`, `app/screens/huntPauseFlow.test.mjs`.
- First-run Hunt is a real FINE round, not a disposable tutorial board. HUD lessons are event-driven and resume-safe. `docs/GAME_REFERENCE.md` owns player-facing copy.

## Content integrity

- `assets/data/huntData.json` is the only live Hunt bank. No parallel override bank.
- The canonical editorial workbook is `docs/content/POLYWORDS_CANONICAL_HUNT.xlsx` (committed 2026-11-20). It is editorial staging, never an automatic runtime feed. After any content change, compare it with live JSON (card IDs, roles, exact phrases, hidden pairs, Word Tracker counts) before claiming parity.
- Word, visible-mask and hidden-pair IDs are persistence contracts. Preserve approved text, roles and stable IDs; never reuse retired IDs for different content. Check Git history and the historical-dispositions index before assigning new IDs.
- Editorial approval precedes difficulty/GPS placement and runtime promotion. The generator and structural validation reject malformed IDs, wrong owner prefixes, bad REAL/trap flags, invalid difficulty/GPS and incomplete Boss hidden content.
- `npm run content:quality` is the CI structural gate; `npm run content:preflight -- --input assets/data/huntData.json` is the local version. Passing either is **not** editorial signoff. Same-headword overlap and length flags are advisory; the ones Pete has reviewed and kept are listed in `docs/CONTENT_WRITING_BIBLE.md` (November 20 section). Do not rewrite approved copy to silence a heuristic.
- Approved validator exceptions are exact ID-and-phrase entries in `tools/content/runtimeHuntValidation.mjs` (`FLY/fly_t6` McFly, `LEAD/lead_r4`). Do not relax the validator globally.
- The preflight SHA-256 is computed on the file as checked out. Pete's Windows tree is CRLF and the repo is LF, so the same content gives two different hashes; compare like with like.
- `assets/data/huntData.v2.json` and `tools/content/_deprecated/mask-rewriter/` are retired; never use them as authority.

## Approved product surfaces

- **Home:** the outdoor night terrace is the approved production Home (`HomeTerraceScreen`); the old indoor Home is DEV-only rollback. Rulings are in `docs/HOME_SCREEN_LOCKDOWN.md` and the live `app/ui/homeTerrace*.ts` files. Do not reopen a Home redesign from old notes.
- **Daily:** deterministic, one attempt per date, five UP-only rounds and two lives; six cards (target plus five distractors), three clues. Entry is two steps: the invitation card (ACCEPT CHALLENGE / NOT NOW) and, on first entry only, a four-step HOW TO PLAY card (`DAILY_INTRO_SEEN_KEY`); afterwards HOW TO PLAY stays as a link. Moving between the cards does not spend the attempt. Daily uses its own writing standard and clue-fit checker (`npm run daily:fit`); a clue must fit the plank in two lines (46 characters is the ordinary authoring limit). The castle breach is built.
- **Polybook:** Polly's book opens from Home to a portrait Living Journal with TODAY / JOURNAL / MASTERY. It must never reveal REALs, traps or hidden pairs because words recur. The MASTERY tally counts MASTERED, KING, BANISHED and active HAUNTED; section ID `BEATEN` is kept for navigation compatibility. Do not delete the old Lexicon rollback components without approval.
- **Polly:** a sharp opponent and trap-setter, not a vocabulary teacher. Relationship Memory V2 is implemented. Master pose art is in `assets/images/polly/master/`. Rig 2 animates face/crown but not a fully articulated body; the whole-image rocking experiment was rejected. Preserve `BROW_FOLLOW = 0.33`. No production full-body animation system without an approved articulation plan.

## Audio, accessibility and native pitfalls

- `app/audio/MusicEngine.ts` owns music; `app/audio/audioSession.ts` the session; `app/audio/sfx.ts` SFX. Audio objects are rebuilt after a long background absence before playback resumes (`app/audio/audioResumePolicy.ts`); preserve the tested order.
- Expo-audio's SDK 57 iOS watchdog fix is carried in `patches/expo-audio+57.0.5.patch` via `patch-package` (`postinstall`). `tools/expoAudioPatch.test.mjs` guards it, so `npm test` fails if dependencies were installed with `--ignore-scripts`. Remove the patch only after a deliberate native upgrade and device background/foreground check.
- Haptics route through `app/utils/haptics.ts`. Hunt and Daily feedback have separate cues. Reduce Motion / Reduce Flashes suppress decoration without changing game decisions, state or required continue gates (`app/game/gameplayFeedbackAccessibility.ts`).
- Native lessons: keep animated transform types stable; protect essential stacked views from flattening; give absolute image layers explicit dimensions on iOS; keep pose layers mounted and switch opacity rather than remounting; trigger arrival reactions from animation completion, not a timer started at screen mount. Use measured layout constants in code, not stale screenshot coordinates.
- Gameplay text sizing is controlled to protect tile fitting; Settings and Polybook keep their own accessibility behavior. Verify native gesture, audio, animation, layout and Bold Text separately from TypeScript/CI.

## Shipping and verification

- CI is `.github/workflows/typecheck.yml` (Quality Checks): Node 24, `npm run typecheck`, `npm test` and `npm run content:quality`. Recheck the **latest branch-head run** after any change; an older green run does not certify a later commit.
- For docs-only changes, check whitespace and references. For code/content, run the relevant tests and the live-bank gate. Report device checks that were not done.
- The public site and privacy/support pages are on the separate orphan `gh-pages` branch. Never merge it with the game branch. Adding network, analytics, crash reporting or ad SDKs requires matching updates to `PRIVACY_TEXT`, the published privacy page and App Store disclosures.
- Licensing is a release gate. Buggie is Public Domain (`assets/fonts/Buggie-LICENSE.txt`, FontSpace link); sound sources are in `assets/audio/LICENSES.md`.
